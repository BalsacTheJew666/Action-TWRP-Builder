# XT2615-1 Nevada — stock-config-based AR9271 ABI probe

## Current evidence

- User's running firmware: `W1WNS36.18-114-1`, Linux `5.15.180-android13-8-00018-g9b2308ac0ad6-ab14563692`, slot `_a`.
- Live `cfg80211` and `mac80211` Build-ID note hashes match the modules recovered from the working TWRP `vendor_boot_a` image. That confirms the reference module *build identity*, though not all bytewise provenance.
- LED-free AR9271 CI produced modules without imports for `__ieee80211_create_tpt_led_trigger` and `__ieee80211_get_radio_led_name`.
- One imported CRC still differs:
  - Running Motorola `mac80211.ko` export `ieee80211_alloc_hw_nm`: **0x561b7fc2**.
  - Latest experimental `ath9k_htc.ko` import: **0x55ebf907**.

## Purpose of this PR

Run a controlled diagnostic using the exact user-provided `/proc/config.gz` dump committed as `ci/xt2615-nevada-stock.config`, verified against SHA256
`e3cdaf997a7e2eb70e441944bdfd9af359aa82e8a2d5cb9534d2bce5fcd4a78a`.

The test keeps the successful LED-free `ATH9K_HTC` Kconfig patch, builds `cfg80211`, `mac80211`, and the Atheros module group as temporary **test** modules, then reports the resulting `ieee80211_alloc_hw_nm` imported CRC without falsifying version/signature metadata.

A green CI run means only that modules compiled and the CRC report was produced. It does not mean the CRC matched or the modules can be loaded.

## Unavoidable differences from the real stock kernel

1. **Toolchain:** The original config was generated by **Android Clang 14.0.7 (r450784e)**. This test uses the Ubuntu runner's Clang 14; future tests should pin Google's prebuilt Android compiler.
2. **LTO:** Stock uses `CONFIG_LTO_CLANG_FULL=y`. Diagnostic CI uses ThinLTO to avoid the FullLTO runner shutdown previously observed.
3. **Symbol whitelist:** Stock `CONFIG_TRIM_UNUSED_KSYMS=y` references an absolute build-host `abi_symbollist.raw` file unavailable in public source. The test explicitly disables trimming to avoid silently copying a nonexistent whitelist.
4. **Module dependency config:** Stock base kernel config has `CONFIG_CFG80211=n`; the running phone loads separate `cfg80211.ko` and `mac80211.ko`. The experimental module build must enable both as `=m` to compile AR9271 modules.
5. **Kernel git/release identity:** The public Motorola tree is pinned for reproducibility, but has not been proven identical to the installed kernel source commit.
6. **KernelSU/TWRP:** This workflow never uses, packages, flashes, or modifies `boot`, `vendor_boot`, `init_boot`, KernelSU or vendor modules.

## How to use

This PR triggers `XT2615-1 Nevada - Stock Config AR9271 ABI Probe` automatically (subject to GitHub Actions approval rules). After it finishes:
- Read `crc-results.txt` in the diagnostic artifact.
- If `MATCH`, proceed to exact Android Clang and complete KMI verification; do **not** install.
- If `MISMATCH`, inspect the exported `ieee80211_alloc_hw_nm` type declarations/headers for a source or config divergence; do **not** force-set symbol CRCs.
- If compilation fails, use the uploaded build log to fix the source/config issue.

**Do not insmod, flash, boot-test, or ship these CI modules as NetHunter yet.**
